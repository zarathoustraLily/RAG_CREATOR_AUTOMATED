> Statut : **proposition à valider** · v0.1 · 2026-10-06

> La manière de le construire est dans `002_strategie.md`.

## 1. L'objectif en une phrase

Construire **RAG Creator**, un programme **100 % local** qui, à partir d'un simple thème
(ex. « Pharmacologie > Champignons > Amanita muscaria »), **collecte, vérifie, structure et
indexe**, **de façon autonome et en tâche de fond**, une base de connaissances (RAG)
**organisée par thèmes hiérarchiques**, conçue pour que **vos modèles locaux** puissent
l'interroger sur **un ou plusieurs thèmes à la fois**, de façon **rapide, pertinente et fiable**.

### Deux rôles de modèles

| Rôle | Modèle | Ce qu'il fait |
|---|---|---|
| **Constructeur** (en tâche de fond) | MiMo-V2.6-Distill-Qwen-9B via `llama-server` — remplaçable | Charte, tri, vérification, enrichissement, graphe, fiches |
| **Consommateur** (à l'usage) | Vos modèles actuels : **Qwen3.8-27B** et **Qwen3.8-Flash-Next** — ou tout autre modèle local | Interroge le RAG multithématique, par appel d'outils (MCP / fonctions) ou via un contexte préparé |
| **Agent de recherche** (à l'usage, optionnel) | MiMo 9B, guidé par prompt, puis **spécialisé par entraînement LoRA si les mesures le justifient** | Mène la recherche multi-étapes à la place du consommateur et lui remet un dossier de preuves compact |

Le RAG ne dépend d'aucun des deux : on peut changer de constructeur ou de consommateur sans
reconstruire la base (seul un changement de modèle d'*embedding* impose de ré-indexer).

## 2. Qui fait quoi

| Vous | Le programme, seul, en arrière-plan |
|---|---|
| Déclarez un thème ou un sous-thème | Rédige la **charte** du thème : définition, périmètre, sous-thèmes, mots-clés FR/EN, synonymes (noms scientifiques, noms vernaculaires), sources prioritaires, types d'affirmations sensibles |
| *(facultatif)* relisez / corrigez la charte | Cherche des sources : web, bases scientifiques, vos fichiers |
| *(facultatif)* déposez fichiers et URL dans la boîte d'entrée du thème | Télécharge, extrait le texte, écarte doublons et pages vides de sens |
| *(facultatif)* tranchez les cas douteux | **Vérifie** chaque document, puis chaque extrait, avec le modèle chargé dans `llama-server` |
| Lisez le rapport de cycle | Découpe, contextualise, extrait entités et relations, indexe |
| Interrogez le RAG (ligne de commande, API, outil MCP pour votre modèle local) | Rédige des **fiches de synthèse sourcées**, mesure la qualité, repère les lacunes et relance la collecte au cycle suivant |

### Exemple

```bash
ragc theme add "Pharmacologie > Champignons > Amanita muscaria"
ragc daemon start
# … le lendemain
ragc report latest
ragc ask "Quels sont les principes actifs d'Amanita muscaria et sur quels récepteurs agissent-ils ?" \
         --theme pharmacologie/champignons
```

### Organisation des thèmes (arbre)

```
pharmacologie/
├── champignons/
│   ├── amanita-muscaria/      alias : amanite tue-mouches, fly agaric
│   └── psilocybe-cubensis/
└── antalgiques/
mycologie/
└── identification/
```

- Chaque nœud de l'arbre est un **silo** avec sa propre charte, sa boîte d'entrée et ses fiches.
- Une question posée sur un thème parent cherche aussi dans **tous ses sous-thèmes**.
- Un même document peut servir plusieurs thèmes **sans être dupliqué**.
- Un sous-thème hérite du contexte de son parent (la charte d'« Amanita muscaria » sait qu'elle
  s'inscrit dans « Pharmacologie > Champignons »).

## 3. Périmètre inclus (v1)

1. **Thèmes hiérarchiques** à profondeur libre, avec alias, statut (actif / en pause / stable) et
   charte modifiable à la main.
2. **Collecte autonome multi-sources** : moteur de recherche local (SearxNG), Wikipédia FR/EN,
   littérature scientifique (Europe PMC / PubMed), listes d'URL, fichiers locaux
   (TXT, Markdown, HTML, PDF, DOCX).
3. **Vérification par le modèle local, à trois niveaux** :
   - *document* : pertinence vis-à-vis de la charte, fiabilité de la source, qualité du texte,
     rattachement au bon nœud de l'arbre ;
   - *extrait* : chaque passage est gardé ou écarté (bruit, hors sujet, publicité…) ;
   - *affirmation sensible* : doses, toxicité, comestibilité, interactions… sont croisées entre
     sources et marquées « concordante / contradictoire / source unique ».
   - Les cas limites passent par un **second avis** du modèle, et éventuellement par vous
     (mode assisté).
4. **Construction d'un RAG de haute qualité** : découpage selon la structure du document,
   contexte ajouté à chaque extrait, questions auxquelles l'extrait répond, entités et relations
   (graphe de connaissances), fiches de synthèse, index hybride (lexical + sémantique + re-classement).
5. **Fonctionnement autonome en tâche de fond** : démon, cycles successifs, reprise après coupure,
   priorité basse, plages horaires, rapport à chaque cycle.
6. **Modèle au choix** : MiMo-V2.6-Distill-Qwen-9B par défaut, tout modèle derrière une API
   compatible OpenAI possible (llama-server, Ollama, vLLM, SGLang, LM Studio), avec un modèle
   différent par étape si on le souhaite.
7. **Utilisation par vos modèles locaux (Qwen3.8-27B, Qwen3.8-Flash-Next…)** :
   - *RAG agentique* : des outils (MCP / appels de fonctions) que le modèle appelle lui-même —
     lister les thèmes, chercher dans un ou plusieurs thèmes, lire une fiche, suivre le graphe ;
   - *RAG classique* : un contexte compact, sourcé et annoté, prêt à injecter ;
   - un proxy compatible OpenAI pour brancher Open WebUI / LM Studio ; la commande `ragc ask`.
8. **Traçabilité et mesure** : chaque décision du modèle est journalisée (prompt et version,
   réponse, scores) ; un jeu d'évaluation est généré pour mesurer la qualité du RAG.

## 4. Hors périmètre (v1)

- Interface graphique web (ligne de commande + rapports Markdown + API suffisent ; v2 possible).
- Appel à un LLM dans le cloud.
- Ré-entraînement des modèles consommateurs (Qwen3.8). *Seule exception prévue : une
  spécialisation LoRA de MiMo comme agent de recherche, déclenchée uniquement si les mesures
  montrent un gain (voir `002_strategie.md` §6.4).*
- OCR d'images et de PDF scannés (le modèle est multimodal : piste pour la v2).
- Contournement de paywalls ou de captchas, collecte de sites qui l'interdisent (`robots.txt`).
- Multi-utilisateur et déploiement sur serveur.

## 5. Ce que veut dire « RAG ultra performant utilisable par un modèle local »

Même avec 262 000 tokens de contexte, un modèle local répond mieux, plus vite et avec moins
d'erreurs à partir de **peu de texte, dense, fiable et bien étiqueté** qu'à partir de 20 passages
bruités ; un long contexte coûte aussi du temps de calcul à chaque question. Le RAG est donc jugé
sur ces critères :

| Critère | Cible proposée | Comment on le mesure |
|---|---|---|
| Rappel de la recherche | Recall@5 ≥ 0,85 | Jeu de questions généré depuis les extraits, filtré, contrôlé par échantillon |
| Qualité du classement | MRR@10 ≥ 0,70 | Même jeu |
| Fidélité des réponses | ≥ 90 % des affirmations appuyées par les passages cités | Juge LLM + échantillon relu par vous |
| Abstention | ≥ 80 % de « je ne sais pas » corrects sur questions sans réponse dans le corpus | Questions pièges du jeu d'évaluation |
| Précision du corpus | ≥ 90 % des documents acceptés jugés pertinents | Échantillon de 50 documents relus |
| Accord de la vérification | ≥ 85 % d'accord avec vos décisions | Jeu de référence de documents annotés |
| Budget de contexte | ≤ 8 000 tokens par recherche pour Qwen3.8-27B / Flash-Next (réglable par modèle consommateur ; 4 000 pour un 9B) | Mesuré à chaque requête |
| Multithématique | une question transversale (ex. pharmacologie × mycologie) trouve les bons thèmes sans qu'on les précise | Questions transversales du jeu d'évaluation |
| Latence | recherche < 300 ms ; < 1,5 s avec re-classement | Sur ~50 000 extraits, GPU grand public |
| Traçabilité | 100 % des extraits et des phrases de fiches renvoient à une source (URL ou fichier + position) | Contrôle automatique |
| Débit d'ingestion | de l'ordre de 1 000 pages par nuit | Hypothèse 2–4 s par extrait, à mesurer |
| Robustesse | reprise après coupure sans perte ni double traitement | Test d'arrêt brutal |

Les cibles chiffrées sont des **propositions** : elles seront calibrées après les premières
mesures réelles sur votre machine (session S12).

## 6. Contraintes

- **Matériel grand public** : GPU 8–12 Go de VRAM (RTX 3060/4060 et plus) ou Apple Silicon
  16 Go et plus ; fonctionnement dégradé possible sur CPU.
- **Inférence via `llama-server`** (llama.cpp), API compatible OpenAI.
- **Souveraineté** : aucune donnée envoyée à un service d'IA externe. Le seul accès réseau est la
  collecte web elle-même, désactivable (mode « fichiers locaux uniquement »).
- **Pas d'infrastructure lourde** : pas de JVM, pas de serveur de base de données obligatoire.
  Python 3.10+, Linux et macOS (Windows au mieux).
- **Ne pas gêner l'usage du poste** : priorité basse, plages horaires, pause à la demande.

## 7. Exigences propres aux domaines sensibles

En pharmacologie et en mycologie, une erreur (dose, toxicité, confusion entre espèces,
comestibilité) peut être dangereuse. Le programme doit donc :

- repérer les **affirmations sensibles** et les **croiser** entre sources indépendantes ;
- **hiérarchiser les sources** : publications scientifiques, agences sanitaires, sociétés savantes
  > encyclopédies > blogs et forums ; signaler les sites commerciaux ;
- livrer ces marquages **avec** les extraits, pour que le modèle local signale la prudence et les
  contradictions au lieu de trancher seul ;
- rappeler que le RAG est un **outil documentaire**, ni un avis médical, ni une aide à
  l'identification de champignons en vue de leur consommation.
